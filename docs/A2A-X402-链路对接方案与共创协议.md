## 1. 架构总览：A2A 与 X402 的分工边界

### 1.1 两组分别负责什么

```
┌─────────────────────────────────────────────────────┐
│                    A2A 组（Agent 通信）                │
│  - Agent 创建与生命周期管理                            │
│  - AgentCard 能力声明                                │
│  - Agent 之间的消息/任务传递（JSON-RPC 2.0）           │
│  - 交易匹配引擎（bid-ask matching + 博弈定价）          │
│  - 信用评分查询接口                                   │
│  - 业务逻辑：议价→达成意向→触发支付→交付                │
│  【不直接操作区块链，不管理私钥，不构造交易】             │
└──────────────────────┬──────────────────────────────┘
                       │
              ┌────────┴────────┐
              │  PaymentGateway │  ← 本文档定义的接口
              │  (薄中间层)      │
              └────────┬────────┘
                       │
┌──────────────────────┴──────────────────────────────┐
│                    X402 组（Agent 支付）               │
│  - X402 协议集成（HTTP 402 Payment Required）         │
│  - 链上支付执行（Injective / Base / Solana）          │
│  - 交易签名与 Gas 管理                               │
│  - 支付验证（链上 confirmations）                     │
│  - TEE 可信执行环境保护私钥与交易逻辑                   │
│  - 链上结算与收据生成                                 │
│  【不关心 Agent 之间在聊什么、议什么价、业务逻辑是啥】    │
└─────────────────────────────────────────────────────┘
```

### 1.2 关键边界原则

| 事项 | A2A 组 | X402 组 |
|---|---|---|
| **私钥** | 禁止接触 | 负责管理（TEE 内） |
| **区块链 RPC** | 禁止直连 | 负责连接 |
| **Agent 业务逻辑** | 唯一拥有者 | 禁止干预 |
| **支付金额/币种** | 决策者（告诉 X402 "付多少"） | 执行者（照付） |
| **支付是否成功** | 信任 X402 的验证结果 | 唯一真相来源 |
| **消息格式** | 定义 A2A message schema | 只读取/附加 payment 字段 |

## 2. 接口契约：两组之间的数据协议

这是本文档最核心的部分。只要两边的输入输出严格遵守这些 schema，两组可以完全独立开发，最后合龙不会出问题。

### 2.1 数据结构

```python
# ============================================================
# 文件：shared/interfaces.py
# 说明：A2A 组和 X402 组共享的数据结构定义
# 地位：CONTRACT — 任何修改需要两组双方同意
# ============================================================

from dataclasses import dataclass, field
from typing import Optional
from enum import Enum


# ---- 资产定义 ----

class Token(str, Enum):
    """支持的结算资产，先只做 USDC，后续扩展"""
    USDC = "USDC"
    # USDT = "USDT"    # 保留，暂不启用


class Chain(int, Enum):
    """支持的链，先只做 Injective"""
    INJECTIVE = "injective-1"   # Injective mainnet chain ID
    # BASE = 8453               # 保留
    # SOLANA = "solana"         # 保留


# ---- 支付请求（A2A → X402）----

@dataclass
class PaymentRequest:
    """
    A2A 组告诉 X402 组：请帮我付这笔钱。
    由 A2A 组构造，传给 X402 组执行。
    """
    # 必填字段
    request_id: str              # 唯一请求 ID，格式 UUID4
    amount: float                # 支付金额，如 1.6 表示 1.6 USDC
    token: Token                 # 结算资产
    recipient_address: str       # 收款方链上地址
    chain: Chain                 # 目标链

    # 可选字段
    payer_address: Optional[str] = None    # 指定付款地址（不填则由 X402 组自行选择）
    description: str = ""                  # 交易描述，用于人类可读日志
    expires_at: Optional[str] = None       # ISO 8601 时间戳，超时后不再执行
    metadata: dict = field(default_factory=dict)  # A2A 组的自定义数据，X402 组原样带回

    def to_dict(self) -> dict:
        """序列化为 JSON，用于跨模块传递"""
        ...

    @classmethod
    def from_dict(cls, data: dict) -> "PaymentRequest":
        """从 JSON 反序列化"""
        ...


# ---- 支付结果（X402 → A2A）----

class PaymentStatus(str, Enum):
    """支付终态"""
    SUCCESS = "SUCCESS"             # 链上已确认
    FAILED = "FAILED"               # 交易失败（revert / out of gas / etc.）
    TIMEOUT = "TIMEOUT"             # 超过 expires_at 未确认
    INSUFFICIENT_FUNDS = "INSUFFICIENT_FUNDS"  # 余额不足


@dataclass
class PaymentResult:
    """
    X402 组告诉 A2A 组：支付结果。
    由 X402 组在支付完成后返回给 A2A 组。
    """
    request_id: str              # 对应 PaymentRequest 的 request_id
    status: PaymentStatus        # 终态

    # 仅 SUCCESS 时有值
    tx_hash: Optional[str] = None           # 链上交易哈希
    block_number: Optional[int] = None      # 确认区块号
    amount_paid: Optional[float] = None     # 实际支付金额
    fee_paid: Optional[float] = None        # 实际 Gas 费
    confirmed_at: Optional[str] = None      # ISO 8601 确认时间

    # 仅 FAILED 时有值
    error_code: Optional[str] = None        # 机器可读错误码
    error_message: Optional[str] = None     # 人类可读错误描述

    metadata: dict = field(default_factory=dict)  # 原样带回 A2A 组的 metadata

    def is_success(self) -> bool:
        return self.status == PaymentStatus.SUCCESS

    def to_dict(self) -> dict:
        ...

    @classmethod
    def from_dict(cls, data: dict) -> "PaymentResult":
        ...


# ---- A2A 消息扩展（含支付证明）----

@dataclass
class PaymentProof:
    """
    支付证明，由买方 Agent 附加到 A2A 消息中发送给卖方 Agent。
    卖方 Agent 通过 X402 组的 verify_payment() 验证其真实性。
    """
    tx_hash: str                 # 链上交易哈希
    payer_address: str           # 付款方地址
    amount: float                # 支付金额
    token: Token                 # 结算资产
    block_number: int            # 确认区块号
    chain: Chain                 # 所在链
    confirmed_at: str            # ISO 8601 确认时间

    def to_dict(self) -> dict:
        ...

    @classmethod
    def from_dict(cls, data: dict) -> "PaymentProof":
        ...


# ---- X402 支付响应（HTTP 402 触发时）----

@dataclass
class X402PaymentRequired:
    """
    当卖方 Agent 收到一个需要支付的服务请求时，
    返回 HTTP 402 + 这个 payload。
    买方 Agent 的 A2A 层解析这个，调用 X402 模块支付。
    """
    payment_id: str              # 支付会话 ID
    amount: float                # 所需金额
    token: Token                 # 币种
    recipient_address: str       # 收款地址
    chain: Chain                 # 目标链
    expires_in_seconds: int      # 支付窗口，如 300（5 分钟）
    description: str = ""        # 付款原因

    def to_http_402_response(self) -> tuple[int, dict, dict]:
        """
        返回 (402, headers, body)
        headers 中包含 X-402-* 标准头部
        """
        ...
```

### 2.2 函数接口

```python
# ============================================================
# 文件：shared/payment_gateway.py
# 说明：PaymentGateway 抽象接口
# 地位：CONTRACT — A2A 组只 import 这个抽象类，不 import 具体实现
#       X402 组负责提供 X402PaymentGateway 具体实现
# ============================================================

from abc import ABC, abstractmethod
from typing import Optional


class IPaymentGateway(ABC):
    """
    A2A 组和 X402 组之间的唯一接口层。
    A2A 组只依赖这个抽象接口，不关心底层是 X402 还是其他协议。
    """

    @abstractmethod
    async def create_payment_from_402(
        self, x402_response: dict
    ) -> "PaymentRequest":
        """
        解析卖方 Agent 返回的 HTTP 402 响应，
        生成标准化的 PaymentRequest。
        A2A 组调用此方法，把原始 402 响应转成结构化请求。
        """
        ...

    @abstractmethod
    async def execute_payment(
        self, request: "PaymentRequest"
    ) -> "PaymentResult":
        """
        执行支付。
        A2A 组调用此方法，阻塞等待直到支付完成（成功/失败/超时）。
        X402 组内部处理：构造交易→TEE 签名→广播→等待确认。
        """
        ...

    @abstractmethod
    async def verify_payment_proof(
        self, proof: "PaymentProof"
    ) -> bool:
        """
        验证支付证明的真实性。
        卖方 Agent 调用此方法，确认买方真的付了钱（链上查询）。
        禁止信任未验证的 proof。
        """
        ...

    @abstractmethod
    def attach_payment_proof_to_message(
        self, a2a_message: dict, proof: "PaymentProof"
    ) -> dict:
        """
        将支付证明附加到 A2A 消息中。
        不修改消息原有内容，仅在顶层增加 X-Payment-Proof 字段。
        """
        ...

    @abstractmethod
    def extract_payment_proof_from_message(
        self, a2a_message: dict
    ) -> Optional["PaymentProof"]:
        """
        从 A2A 消息中提取支付证明。
        如果没有支付证明，返回 None。
        """
        ...
```

### 2.3 接口稳定性承诺

- **v1.0 封板后，任何 schema 字段增删需要两组双方 Approve**
- 新增字段：可以加 `Optional` 字段，不影响现有代码
- 删除字段：必须有 2 周的 deprecated 警告期，不可直接删除
- 字段重命名：视为删除+新增，禁止
- `PaymentRequest.request_id`、`PaymentResult.status`、`PaymentProof.tx_hash` 三个字段永不废弃

## 3. 时序流程：一笔 Agentic Payment 的完整生命周期

```
买方 Agent (A2A)          卖方 Agent (A2A)          X402 模块 (买方)        Blockchain
     │                         │                         │                    │
     │  1. A2A 询价请求         │                         │                    │
     │────────────────────────▶│                         │                    │
     │                         │                         │                    │
     │  2. HTTP 402 Payment    │                         │                    │
     │     Required + X402头    │                         │                    │
     │◀────────────────────────│                         │                    │
     │                         │                         │                    │
     │  3. create_payment_from_402(x402_response)         │                    │
     │─────────────────────────────────────────────────▶│                    │
     │                         │                         │                    │
     │  4. PaymentRequest      │                         │                    │
     │◀─────────────────────────────────────────────────│                    │
     │                         │                         │                    │
     │  5. execute_payment(request)                      │                    │
     │─────────────────────────────────────────────────▶│                    │
     │                         │                         │                    │
     │                         │       6. 构造交易        │                    │
     │                         │       (TEE 内签名)       │                    │
     │                         │─────────────────────────│                    │
     │                         │                         │   7. broadcast     │
     │                         │                         │───────────────────▶│
     │                         │                         │                    │
     │                         │                         │   8. confirmed     │
     │                         │                         │◀───────────────────│
     │                         │                         │                    │
     │  9. PaymentResult       │                         │                    │
     │     (SUCCESS + tx_hash) │                         │                    │
     │◀─────────────────────────────────────────────────│                    │
     │                         │                         │                    │
     │  10. attach_payment_proof_to_message(             │                    │
     │      原始A2A消息, proof)   │                         │                    │
     │─────────────────────────────────────────────────▶│                    │
     │                         │                         │                    │
     │  11. A2A 请求 +         │                         │                    │
     │      X-Payment-Proof    │                         │                    │
     │────────────────────────▶│                         │                    │
     │                         │                         │                    │
     │                         │  12. extract_payment_    │                    │
     │                         │      proof_from_message()│                    │
     │                         │─────────────────────────│                    │
     │                         │                         │                    │
     │                         │  13. verify_payment_     │                    │
     │                         │      proof(proof)        │                    │
     │                         │─────────────────────────│                    │
     │                         │                         │                    │
     │                         │  14. True ✓              │                    │
     │                         │◀─────────────────────────│                    │
     │                         │                         │                    │
     │  15. A2A 服务响应        │                         │                    │
     │◀────────────────────────│                         │                    │
     │                         │                         │                    │
```

### 关键步骤说明

| 步骤 | 谁负责 | 逻辑 | 出错处理 |
|---|---|---|---|
| 1-2 | 卖方 A2A | 卖方 Agent 判断请求需要支付，返回 HTTP 402 + X402 头 | — |
| 3-4 | 买方 A2A → X402 | 解析 402 响应，生成标准 PaymentRequest | 如果 402 格式非法，X402 模块返回错误，买方 A2A 中止交易 |
| 5-9 | X402 | TEE 内签名 + 广播 + 等待确认 | 任何失败返回 FAILED/TIMEOUT，买方 A2A 重试或放弃 |
| 10-11 | 买方 A2A → X402 | 把 payment proof 附加到 A2A 消息 | — |
| 12-14 | 卖方 A2A → X402 | **链上验证 payment proof** | **这一步绝对不能跳过**（见红线 #1） |
| 15 | 卖方 A2A | 验证通过后执行服务 | — |

## 4. Mock 方案：独立开发期的假数据规范

两组在独立开发时，使用统一的 Mock 数据，确保各自的单元测试和集成测试在合龙前就能覆盖完整流程。

### 4.1 A2A 组 Mock（模拟 X402 模块）

```python
# 文件：a2a_team/mocks/mock_payment_gateway.py

class MockPaymentGateway(IPaymentGateway):
    """
    A2A 组开发时使用。
    不发起真实链上交易，直接返回模拟成功结果。
    行为可配置：成功 / 失败 / 超时 / 余额不足。
    """

    def __init__(self, behavior: str = "always_success"):
        """
        behavior 可选值：
        - "always_success": 每次都成功
        - "always_timeout": 每次都超时
        - "insufficient_funds": 每次都余额不足
        - "fail_then_success": 第一次失败，第二次成功（测重试逻辑）
        """
        self.behavior = behavior
        self._attempts = 0

    async def execute_payment(self, request: PaymentRequest):
        self._attempts += 1
        if self.behavior == "always_success":
            return PaymentResult(
                request_id=request.request_id,
                status=PaymentStatus.SUCCESS,
                tx_hash=f"0x{'a'*64}",  # 固定 mock tx hash
                block_number=12345678,
                amount_paid=request.amount,
                fee_paid=0.001,
                confirmed_at="2026-07-23T00:00:00Z",
            )
        elif self.behavior == "always_timeout":
            return PaymentResult(
                request_id=request.request_id,
                status=PaymentStatus.TIMEOUT,
                error_message="Mock timeout",
            )
        # ... 其他模式
```

## 5. 合龙 Checklist

在两组代码合并前，按此清单逐项验证。**全部通过才能合龙。**

### 5.1 接口兼容性

- [ ] `PaymentRequest` 字段双方理解一致（每个字段的含义、单位、格式）
- [ ] `PaymentResult` 所有终态（SUCCESS / FAILED / TIMEOUT / INSUFFICIENT_FUNDS）都有测试覆盖
- [ ] `PaymentProof` 在 A2A 消息中的序列化/反序列化正确
- [ ] Mock 替换为真实实现后，所有现有测试仍然通过

### 5.2 流程完整性

- [ ] **Happy Path**：买方询价 → 收到 402 → 支付 → 附加 proof → 卖方验证 → 交付
- [ ] **余额不足**：买方余额不足 → 返回 INSUFFICIENT_FUNDS → A2A 组向用户提示
- [ ] **支付超时**：超过 expires_at → 返回 TIMEOUT → A2A 组优雅处理
- [ ] **重复支付保护**：同一 PaymentRequest 不会被执行两次
- [ ] **卖方验证失败**：卖方在 A2A 层拒绝服务，不执行任何操作

### 5.3 边界条件

- [ ] 金额精度：测试 0.000001 USDC 和 999999.999999 USDC
- [ ] 并发支付：多个 Agent 同时发起支付，request_id 不冲突
- [ ] 链分叉处理：X402 组等待足够 confirmations（Injective 建议 1 个区块即可，其他链至少 6 个）
- [ ] 网络中断重连：X402 模块断网后的重试策略

### 5.4 安全验证

- [ ] PaymentProof 必须通过链上验证才放行（Mock 也要模拟此行为）
- [ ] 私钥不在任何日志/A2A 消息/HTTP 响应中出现
- [ ] request_id 确实是 UUID4，不是可预测的序列号

## 6. 开发注意事项

### 6.1 通用

1. **接口先行，实现后行。** 本文档的 `shared/interfaces.py` 和 `shared/payment_gateway.py` 是最先要提交到仓库的文件。两组各自从 `git pull` 拉取，然后基于抽象接口开发。

2. **每天同步接口版本。** 每天开始开发前，先 pull 最新代码。如果发现接口有变动，在群聊里 ping 对方确认。

3. **commit message 标注模块。** 格式：`[A2A] xxx` / `[X402] xxx` / `[SHARED] xxx`。合龙时一眼能看出改动归属。

4. **测试用例优先于业务代码。** 每个接口方法先写测试（用 Mock），再写实现。合龙时两组测试全部通过 = 80% 的兼容性问题已经消除了。

5. **单元测试不启动真实链。** 两组各自的单元测试只能用 mock，不要依赖真实 RPC。集成测试另说。

### 6.2 A2A 组注意事项

1. **不要自己算 Gas。** Gas 估算、Gas Price 策略全部交给 X402 组。你只告诉对方"付多少钱"（amount），不告诉对方"怎么付"。
2. **不要假设支付是即时的。** `execute_payment()` 是异步的，可能需要几秒（等待区块确认）。UI 上要有 loading/pending 状态。
3. **402 响应可能有多种变体。** X402 协议目前还在演化中，不同版本的 402 header 字段可能略有差异。统一通过 `create_payment_from_402()` 来解析，不要自己解析 raw headers。
4. **PaymentProof 对 A2A 组是不透明的。** 买方 A2A 组只负责"附带"proof，不负责"验证"proof。卖方 A2A 组负责"传递"proof 给 X402 模块验证，不负责"解读"proof。
5. **价格单位用浮点数，内部统一。** `amount: 1.6` 表示 1.6 USDC，不要用 wei/最小单位。如果 X402 组需要转换，他们自己做。

### 6.3 X402 组注意事项

1. **PaymentRequest.amount 是"人类可读"的金额。** `1.6` = 1.6 USDC。你们在构造链上交易时需要自己转换成最小单位（USDC 是 6 位小数 → `1600000`）。
2. **PaymentResult 必须在确认后才返回。** 不要广播交易后立刻返回 SUCCESS。等待至少 1 个区块确认（Injective 出块时间 ~2s）。
3. **X402 header 的格式遵循 Coinbase 标准。** 参考 [github.com/coinbase/x402](https://github.com/coinbase/x402)。不要自己发明 header 名字。
4. **TEE Attestation 不是支付流程的一部分。** TEE 的 Remote Attestation 是在 Agent 启动时做的（证明"这个 Agent 的支付逻辑可信"），不是在每笔支付时做的。不要把 attestation report 塞进 PaymentProof。
5. **不要修改 A2A 消息体。** `attach_payment_proof_to_message()` 只在消息的**顶层**增加 `x_payment_proof` 字段，不要修改 message 内部任何内容。

## 7. 绝对不能触及的红线

以下是硬性规则。**违反任何一条，合龙时必须重做，没有例外。**

### 🔴 红线 #1：卖方绝对不能跳过链上支付验证

```python
# ❌ 绝对禁止
def handle_a2a_request(message):
    proof = extract_payment_proof(message)
    if proof is not None:  # 有 proof 字段就信了
        return deliver_service()

# ✅ 必须这样
def handle_a2a_request(message):
    proof = extract_payment_proof(message)
    if proof is None:
        return error("Payment required")
    if not payment_gateway.verify_payment_proof(proof):  # 必须链上验证
        return error("Payment verification failed")
    return deliver_service()
```

**原因**：攻击者可以伪造 A2A 消息中的 payment proof 字段。只有链上查询返回的 tx_hash 是真的。

### 🔴 红线 #2：A2A 组代码中绝对不能出现私钥/助记词

```python
# ❌ 绝对禁止在 A2A 模块中出现
PRIVATE_KEY = "0x..."
MNEMONIC = "abandon abandon ..."
web3.eth.account.from_key(...)
Account.sign_transaction(...)

# ✅ 私钥只存在于 X402 组的 TEE Enclave 中
# A2A 组通过 PaymentGateway.execute_payment() 发起支付
# 私钥永远不会跨越 A2A ↔ X402 的边界
```

### 🔴 红线 #3：绝对不能直接拼接用户输入构造交易

```python
# ❌ 绝对禁止
amount = request.args.get('amount')
tx = contract.functions.transfer(recipient, int(amount) * 10**6)

# ✅ 必须通过接口
payment_request = PaymentRequest(
    amount=float(amount),  # 类型校验在 PaymentRequest 构造时完成
    ...
)
result = await gateway.execute_payment(payment_request)
```

### 🔴 红线 #4：绝对不能在生产代码中使用 Mock

Mock 只用于单元测试和独立开发期。合龙后的集成测试和任何部署到测试网/主网的代码，必须使用真实的 X402 实现。如果发现 Mock 泄漏进了生产路径，立即回滚。

### 🔴 红线 #5：支付请求绝对不能无超时

```python
# ❌ 绝对禁止
PaymentRequest(
    amount=1.6,
    token=Token.USDC,
    recipient_address="...",
    chain=Chain.INJECTIVE,
    # expires_at 没有填！
)

# ✅ 必须设置超时
PaymentRequest(
    ...
    expires_at=(datetime.utcnow() + timedelta(minutes=5)).isoformat(),
)
```

### 🔴 红线 #6：绝对不能不处理支付终态

```python
# ❌ 绝对禁止：只处理 SUCCESS
result = await gateway.execute_payment(request)
print(f"Paid! Tx: {result.tx_hash}")

# ✅ 必须覆盖所有终态
result = await gateway.execute_payment(request)
if result.status == PaymentStatus.SUCCESS:
    ...
elif result.status == PaymentStatus.FAILED:
    # 告诉用户交易失败，可能原因：revert / out of gas
    ...
elif result.status == PaymentStatus.TIMEOUT:
    # 告诉用户支付超时，可以重试
    ...
elif result.status == PaymentStatus.INSUFFICIENT_FUNDS:
    # 告诉用户余额不足
    ...
```

## 8. 共创协议

### 8.1 协作原则

1. **接口变更是同步事件。** 任何需要修改 `shared/interfaces.py` 的 PR，必须在合并前获得另一方（至少一人）的 Approve。不能单方面改接口。
2. **谁定义谁维护。** `PaymentRequest` 由 A2A 组主导定义（因为 A2A 组最清楚需要什么支付参数）。`PaymentResult` / `PaymentProof` 由 X402 组主导定义（因为 X402 组最清楚链上能返回什么）。`IPaymentGateway` 由两组共同维护。
3. **问题公开，不等。** 如果发现接口有问题，直接在 GitHub Issue 里开一个 issue，assign 两组各一人。不要在私下聊天里解决——Issue 是唯一真相来源。
4. **Mock 行为对齐。** 当 A2A 组需要新的 mock 行为（比如需要模拟"先超时再成功"），A2A 组在 `MockPaymentGateway` 中加，通知 X402 组同步接口。反之亦然。
5. **Commit 粒度小，回滚成本低。** 每个 commit 最好只做一件事。合龙时如果发现某个 commit 有问题，可以精确 revert 而不是整 PR 回滚。

### 8.2 接口变更流程

```
1. 提议者开 GitHub Issue
  标题: [INTERFACE] 提议：PaymentRequest 增加 max_fee 字段
  内容：为什么需要这个字段 / 类型 / 默认值 / 对现有代码的影响

2. 另一方在 Issue 中回复：Approve / Request Changes
  如果 Approve → 进入步骤 3
  如果 Request Changes → 讨论到达成一致

3. 提议者提 PR
  分支命名：interface/add-max-fee
  修改 shared/interfaces.py
  更新 shared/test_fixtures.py
  两组各自的 mock 同步更新
  PR 描述中引用原始 Issue

4. 另一方 Review & Approve & Merge

5. 两组各自 pull main，继续开发
```

### 8.3 分支策略

```
main
├── a2a/agent-discovery        # A2A 组的功能分支
├── a2a/matching-engine        # A2A 组的功能分支
├── x402/payment-executor      # X402 组的功能分支
├── x402/tee-enclave           # X402 组的功能分支
├── interface/<change-name>    # 接口变更专用分支（双方共同 review）
└── integration/merge-test     # 合龙测试分支
```

### 8.4 每周同步（建议 15 分钟）

| 议题 | 说明 |
|---|---|
| 接口变更 | 本周有无接口 PR 需要 review？ |
| 阻塞项 | 有什么是依赖对方才能继续的？ |
| Mock 更新 | 对方的 Mock 是否还满足自己的测试需求？ |
| 下周计划 | 下周各自计划做哪些可能影响接口的改动？ |
